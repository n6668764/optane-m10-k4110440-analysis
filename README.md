# Intel Optane M10 K4110440 离线静态分析资料

研究目标：恢复读取、写入 3D XPoint 存储单元数据所涉及的控制器寄存器和操作。

本仓库存档了对 `SB_K4110440_x64.dll` 的三轮静态分析。所有现有报告、提取的固件和段、反汇编片段、原始证据切片、签名验证结果及分析脚本均保存在完整 ZIP 中；三份主要报告同时单独提供，便于直接阅读。

## 当前结果

| 项目 | 静态分析结果 |
|---|---|
| 内嵌固件 | 已提取 585,728 字节 K4110440-005 固件；已建立 EFLI 段映射 |
| 目标代码 | PBUF/VBUF 中存在可反汇编的 ARM/Thumb 代码 |
| 数据读入口 | `E2B14 → E2DC0 → E7AFC → E7942`，内部 opcode `0x0` |
| 数据写入口 | `E2C10 → E2DD6 → E7A1C → E7942`，内部 opcode `0x2` |
| 单次软件传输 | 四个 32 位字，即 16 字节 |
| 控制器窗口 | `0x03810000`、`0x03820000` |
| 关键偏移 | 命令 `+0x1C`，地址 `+0x20`，读数据 `+0x30..3C`，写数据 `+0x40..4C`，状态 `+0x08` |
| 调用证据 | 固定图案写入后同地址读回比较；读出、修改、写回 |
| 初始化规则 | 已恢复 44 条条件修改记录，涉及 32 个配置寄存器编号 |

已恢复的是控制器内部介质接口的数据流。外部 3D XPoint 行/列/阵列地址、引脚命令及时序、AHU14132 型号对应关系、ECC 和持久化条件尚未证实。部分写流程使用的 opcode `0xB` 也尚不能命名为 commit/program/flush。内部地址和操作码不能直接视为主机 NVMe 命令或裸芯片接口规范。

## 分析边界与继续研究

全程只进行了文件读取、结构解析、静态反汇编、签名数学验证与独立转写算式的数值核对。没有执行 DLL、更新器、固件或目标模拟器，没有访问或更新硬件。数值核对不等于设备行为验证。

下一步重点是上追地址构造和容量边界、恢复 A/B/flag 与 `0xB` 的含义，以及追通正常请求的 LBA/缓存/DMA 到介质地址的映射。

分析脚本使用 Python，签名验证使用 cryptography，反汇编使用 LLVM 的 llvm-objdump。部分脚本记录了原分析机器的工具路径；在其他环境复用时需先调整路径。`*_arm_static.elf` 是为静态反汇编构造的包装文件，本次未执行。
